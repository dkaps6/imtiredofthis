## Why this amendment is necessary

The frozen plan described source B as an `m89_2024_2025_synthesis_trace.csv` regenerated by the later M89 empirical-fair-probability workflow. When the still-valid M89 empirical artifact (`run 34727250923`, artifact `10308376403`) was materialized, the available feature file was `qb_synthesis_trace_with_identity.csv`, with a different reconstruction footprint: 894 rows and no Week-1 rows that matched the 771-row Vegas cohort. Joining the frozen 771 Vegas rows against that later reconstruction yielded only 721 rows; all 50 unmatched rows were Week 1 (28 in 2024, 22 in 2025). Overlapping feature values also differed materially from the PD3 casebook for multiple frozen dimensions.

Therefore that later reconstruction is not the authority-exact feature source for this experiment. Using it would change the analog geometry relative to the QB authority lineage that generated the Vegas benchmark.

The PD3 casebook is the correct pregame feature source because:
1. it is the exact QB casebook consumed by the authority-exact benchmark workflow;
2. it has the expected 884-row 2024-2025 authority population;
3. it contains all 17 frozen pregame feature columns unchanged;
4. it joins all 771 `CURRENT_PRODUCTION_ORDER` QB Vegas rows one-to-one.

This is a **source-lineage correction only**, made before 2025 outcomes are opened. No feature was added, removed, reweighted, or redefined.

## Additional confirmation-boundary hardening

The real authority-exact Vegas file uses grading-column names not covered by the first defensive outcome list (for example `actual_result`, `actual_side`, `win_loss_push`, and `unit_result`). The real-data confirmation orchestration therefore does **not** rely on the generic raw-data splitter for scientific isolation.

Instead it is explicitly two-phase:
1. `PREPARE` reads only safe identity/scope columns from the Vegas file and only the frozen 17 pregame features from the PD3 casebook, then persists the scaler/density/neighborhood geometry.
2. `CONFIRM` is the single outcome-opening execution. It verifies the exact Vegas artifact hash, loads the already-frozen geometry, reads `unit_result`, derives the preregistered 2024 neighbor-win support rule, applies it unchanged to the frozen 2025 neighborhoods, and evaluates the frozen 2025 gates once.

No post-result change to source, features, metric, `k`, density percentile, evidence rule, or pass/fail gates is authorized.
