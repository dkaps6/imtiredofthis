## Pre-result fidelity amendment record

The original plan was frozen at commit `222c78cb0314e79e0f9ce6e147ab127a30f68f10`. No candidate distribution was implemented, run, or inspected before the clarifications below were made.

Direct rereads of the exact merged PR #556 evaluator and the repository's WR-R3 width implementation established three details that should be explicit rather than left to interpretation:

1. **Exact #556 error-history universe.** The PR #556 panel used for same-player error history contains target seasons **2021-2024 only**. The 2020 component artifact exists only to fit the frozen ensemble weights applied to 2021; 2020 errors do **not** enter `prior8_yard_mae`. Cross-season history therefore begins only where target-panel history exists (for example 2021 -> 2022), exactly matching #556.
2. **Clustered paired bootstrap.** Because the same RB contributes repeated player-games, the primary CRPS bootstrap will resample **player clusters**, not individual rows. Each sampled `player_key` contributes all of that player's eligible rows, preserving within-player dependence. The replicate count (`10,000`), deterministic seed (`42027`), paired baseline/candidate comparison, and frozen `>=0.95` probability gate are unchanged. This is a prospective statistical-conservatism correction, not a result-driven gate change.
3. **Exact empirical-percentile convention.** Match the already-implemented WR-R3 width precedent: maintain the sorted strictly-prior reference values and compute `difficulty_score = bisect_right(reference, prior8_yard_mae) / len(reference)`. Process by `(season, week)` groups: every row in a target week is scored against the reference pool available **before that week**, and only after the whole week is scored are that week's eligible feature values inserted into the reference pool. This removes any arbitrary within-week player ordering and keeps the mapping fully pregame.

No width coefficient, onset percentile, cap, target seasons, evaluation thresholds, candidate transformation, or scientific success gate was changed by these amendments.

## Authority / purpose

This experiment advances the one RB-PD2 authorization that PD3/PD4/PD5/PD6 never tested: **strictly-prior same-player difficulty -> uncertainty / Monte Carlo width calibration rather than a mean offset**.

Lineage is fixed before candidate output:

- Original RB-PD2 (`RB_PLAYER_ERROR_PERSISTENCE_DETECTED`) found yard-difficulty persistence on 2025: Spearman `0.33056`, Q4-Q1 next-game absolute-yard-error gap `+16.696 yd`.
- PR #556 independently reproduced the mechanism on a non-2025, current-production-equivalent season-long route across 2021-2024: pooled yard-difficulty Spearman `0.377996`, Q4-Q1 gap `+18.143 yd`, positive direction in all 4 seasons. Its frozen disposition explicitly unlocked the yard uncertainty-width lane for a separately preregistered experiment.
- PD3/PD4/PD5 tested mean corrections and failed their own gates. PD6 was never launched. The repository reconciliation explicitly confirms none of PD3-PD6 implemented the difficulty -> MC-width leg.
- The RB ceiling-compression stop rule remains binding: do not reopen STACK6 slicing or another retrospective residual/carry-tail tuning family. This study is different: it leaves the football mean, carries, YPC, allocation, residual pool, and all sportsbook logic unchanged and asks whether a pregame player-specific reliability signal should widen only the predictive distribution around the already-authorized mean.

The question is:

> Holding the current-production-equivalent RB rushing-yard mean exactly fixed, does a conservative, prospectively frozen widening of the canonical Monte Carlo distribution for historically difficult-to-project RBs improve proper scoring and interval/tail calibration?

A PASS is only a **research qualification** for a later isolated production-shadow / forward-validation design. It does not directly authorize production.

## Why V1 is rushing-yard width only

PR #556 unlocked both carry-width and yard-width research, but they do not share the same implementation seam.

- Rushing-yard dispersion already exists as a continuous Monte Carlo distribution and can be widened mean-neutrally after canonical simulation.
- Carry dispersion is generated by finite-team multinomial allocation. A legitimate carry-width change must preserve team-rush conservation and opportunity competition; simply stretching integer carry draws would create a second architectural hypothesis and can break conservation.

Therefore V1 tests **yard width only**, the stronger replicated signal and cleaner seam. Carry-width remains authorized research real estate but is explicitly deferred; failure or success here does not disposition the carry-width question.

## Frozen candidate mapping

Use the project's already-preregistered conservative width precedent from WR-R3 Lane B, chosen here before any RB width result is observed:

`difficulty_score = strict_prior_percentile(prior8_yard_mae)`

`width_mult = 1.0 + 0.30 * clip((difficulty_score - 0.50) / 0.50, 0.0, 1.0)`

Consequences are fixed:

- bottom 50% difficulty: unchanged (`1.00x`);
- difficulty above the median: monotonic widening;
- maximum widening: `1.30x`;
- no narrowing;
- no coefficient, percentile cutoff, cap, subgroup, or transform search after output.

### Mean-neutral draw transformation

Apply the width candidate only to the already-mean-aligned RB rushing-yard draw array:

1. `mu = mean(baseline_draw)`;
2. `candidate_raw = max(0, mu + width_mult * (baseline_draw - mu))` elementwise;
3. if `mean(candidate_raw) > 0`, re-anchor non-negatively with
   `candidate_draw = candidate_raw * (mu / mean(candidate_raw))`;
4. otherwise fail closed.

This preserves the target football mean after the non-negative floor. It changes no carry draw, team rush total, player share, YPC input, rush-efficiency state, receiving market, or sportsbook input.

The candidate is a distribution selector only. Point projection remains `ensemble_proj` exactly.

### B. Mean neutrality / point protection

1. Candidate-vs-baseline row mean max absolute delta `<=1e-8`.
2. Pooled rushing-yard point MAE candidate vs baseline delta absolute value `<=1e-8`.
3. No carry/mean/YPC/allocation input is changed.

### C. Primary proper-score improvement

On the full eligible population:

1. Candidate mean CRPS improves by at least **0.5%** vs baseline.
2. Player-clustered paired bootstrap probability of lower candidate pooled CRPS is `>=0.95`.

### D. Targeted high-difficulty improvement

On the frozen top difficulty quartile:

1. Candidate mean CRPS improves by at least **1.0%** vs baseline.
2. Candidate 80% absolute coverage gap is strictly smaller than baseline.
3. Candidate 90% absolute coverage gap is strictly smaller than baseline.

This gate prevents a generic width change from qualifying without helping the predeclared player-difficulty regime that motivated it.

### E. Pooled interval calibration protection

Across all eligible rows:

1. 80% absolute coverage gap is non-worse vs baseline.
2. 90% absolute coverage gap is non-worse vs baseline.
3. At least one of the two pooled coverage gaps improves strictly.

### F. Upper-tail protection / ceiling-compression relevance

Using empirical draw probabilities:

1. 100-yard exceedance Brier score improves strictly.
2. 50-yard exceedance Brier score is non-worse.
3. 75-yard exceedance Brier score is non-worse.

This does not retune the M95T residual/tail mechanism. It only checks whether the independent PD2 difficulty-width signal improves probabilistic treatment of the known high-end rushing-yard problem.

### G. Season robustness

1. Candidate CRPS is lower than baseline in at least **3 of 4** target seasons.
2. 2023 and 2024 pooled CRPS are each non-worse.
3. High-difficulty-quartile CRPS improves in at least **3 of 4** seasons with adequate slice support (`>=100` eligible rows for the slice).

No season may be removed after output.
